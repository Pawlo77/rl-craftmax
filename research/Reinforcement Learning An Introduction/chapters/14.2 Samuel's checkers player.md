# Samuel's checkers player (Sutton & Barto, Chapter 14, case study 2)

> [!abstract] TL;DR
> A checkers program that looks ahead by minimax search, scores the leaves of the search tree with a linear function of board features, and improves by two learning methods: saving searched values (rote learning) and shifting the feature weights toward the minimax value of a search from the next position (learning by generalization). The second is the same idea as temporal-difference (TD) learning with function approximation, but it lacked a reward or terminal-value anchor, so its value function could become consistent without being useful.

## Problem

- **Goal**: learn to play checkers well, using lookahead search together with a learned evaluation of board positions, so that effort goes into learning instead of into the complexity of the game.
- **Why games**: they are simpler than problems taken from life while still allowing a study of how heuristic procedures and learning work together; checkers is simpler than chess.
- **Difficulty**: a position's worth is not given. The learner must produce its own evaluation of positions from play, without a table of true values and without an explicit reward.

## Conceptual framework

- **Position, on-move position**: a checkers board. An on-move position is one where the program moves next; positions where the opponent moves next are the other kind.
- **Ply**: one level of the search tree, that is, one move by one side.
- **Heuristic search**: from the current position grow a tree of continuations, score the terminal (leaf) positions with an approximate value function and back the scores up to the root; see [[08b Trajectory sampling, search, MCTS]]. Some versions used search control analogous to alpha-beta cutoffs, which stop expanding branches that cannot change the result.
- **Scoring polynomial**: the value function that scores leaves, a linear combination of board features (a weighted sum of numbers describing the position), that is, linear function approximation as in [[09a Function approximation and linear methods]].
- **Minimax and backed-up score**: working backward from the scored leaves, each position gets the score of the position resulting from the best move, assuming the program always maximizes the score and the opponent always minimizes it. That score is the position's backed-up score; at the root it yields the move to play, assuming the opponent evaluates positions by the same criterion from its own side.
- **Backup**: an update of a value toward a value computed from successor positions, as defined in [[08a Models, planning, Dyna]].
- **Self-play**: the program plays games against another version of itself.

## Approach

The program plays by minimax search from each current position and learns in two ways.

1. **Rote learning**: save a description of every board position met in play together with its backed-up value.
   - If a stored position later appears as a leaf of a search, its stored value stands in for the results of one or more earlier searches, so the effective search depth grows.
   - To give a sense of direction (otherwise nothing favored the most direct path to a win), a position's value is decreased by a small amount each time it is backed up one ply. Among positions whose scores differ only by ply count, the program then takes a low-ply one when winning and a high-ply one when losing.
   - This discounting-like device was essential to successful learning; see discounting in [[03a MDP setting and returns]].
2. **Learning by generalization**: adjust the weights of the scoring polynomial, so that learning transfers to positions never seen, which a stored table cannot do.
   - It trains by self-play and makes a backup after each move.
   - The backup is made to the value of an on-move position, after one move by each side has led to a second on-move position; the target is the minimax value of a search launched from that second position.
   - The backup is therefore one full move of real events followed by a search over hypothetical events. The actual algorithm was more complex for computational reasons.
3. **Piece advantage as the only anchor**: the program had no explicit rewards. The weight of its most important feature, the piece advantage (own pieces minus the opponent's, kings (promoted pieces) counting more, with refinements so that trading pieces is better when winning than when losing), was fixed and not learnable.
   - The program's goal was thus to improve its piece advantage, which in checkers is highly correlated with winning.
4. **Feature selection**: the generalization version could also search through sets of features to find those most useful in the value function.

### Results as the book reports them

- **Rote learning**: slow but continuous improvement, most effective in the opening and the endgame; the program became a "better-than-average novice" after many games against itself, against several human opponents and from book games (recorded games used as supervised training).
- **Generalization**: play approached "better-than-average"; fairly good amateurs called it "tricky but beatable". It developed a good middle game but stayed weak in the opening and endgame, the opposite profile from rote learning.
- **Later version**: added refinements to the search such as alpha-beta pruning, extensive use of the supervised mode ("book learning"), and hierarchical lookup tables called signature tables in place of the linear function. It played much better than the earlier program, though still not at master level.

## Math

The book gives no formulas for this case study; the equations below formalize the description in its notation and are labelled as derived here.

**Notation.**

| Symbol | Meaning |
|--------|---------|
| $S_t$ | the $t$-th on-move position of a game |
| $\mathbf{x}(s)$ | feature vector of position $s$, as in [[09a Function approximation and linear methods]] |
| $\mathbf{w}$ | weight vector of the scoring polynomial; the weight on the piece-advantage feature is fixed |
| $\hat v(s,\mathbf{w})$ | score of position $s$, the approximate value |
| $\alpha$ | step size, as in earlier notes |
| $v_{\text{mm}}(s)$ | minimax value of a search launched from position $s$ (the book describes the small per-ply decrease only for rote learning; whether it applies here is not stated) |

**Scoring polynomial** (formalized here):

$$
\hat v(s,\mathbf{w}) = \mathbf{w}^{\top}\mathbf{x}(s)
$$

- A linear value function over board features; it scores leaves of the search tree and, through the backed-up scores, the root.

**Backup toward a search value** (formalized here, as a gradient step on the squared difference):

$$
\mathbf{w} \leftarrow \mathbf{w} + \alpha \Big[ v_{\text{mm}}(S_{t+1}) - \hat v(S_t,\mathbf{w}) \Big] \mathbf{x}(S_t)
$$

- The score of an on-move position moves toward the minimax value found from the next on-move position, one real move by each side later. This is a TD-style update ([[06 Temporal-difference learning]]) whose target is a search value instead of a single successor's estimate; the learned weights follow the same gradient rule as in [[09a Function approximation and linear methods]].
- Only modifiable weights change; the fixed piece-advantage weight is left as it is.

## Dataset example

One row per backup of generalization learning: an on-move position, its features, its current score and the search value it is moved toward. All values are illustrative (the book prints no data); they are internally consistent for $\mathbf{w} = (10,\ 0.5,\ 0.2)$ with the first weight fixed.

| step | position $S_t$ | features $\mathbf{x}(S_t)$: piece advantage, center control, mobility | $\hat v(S_t,\mathbf{w})$ | target $v_{\text{mm}}(S_{t+1})$ | error |
|------|----------------|---------------------|-----------|-----------|-------|
| 1 | on-move, one piece up | $(1, 2, 3)$ | $11.6$ | $12.0$ | $+0.4$ |
| 2 | on-move, level | $(0, 1, 4)$ | $1.3$ | $0.9$ | $-0.4$ |
| 3 | on-move, one piece down | $(-1, 3, 2)$ | $-8.1$ | $-7.6$ | $+0.5$ |

- **Column to symbol**: the features are $\mathbf{x}(S_t)$, the score is $\hat v(S_t,\mathbf{w}) = \mathbf{w}^{\top}\mathbf{x}(S_t)$ (row 1: $10 + 1 + 0.6$), the target is $v_{\text{mm}}(S_{t+1})$ and the error is their difference; only piece advantage is named by the book, the other features are invented here.
- **Update of row 1** (formalized here, $\alpha = 0.01$): the weight change is $0.01 \cdot 0.4 \cdot (1, 2, 3) = (0.004, 0.008, 0.012)$, of which only the last two components are applied because the first weight is fixed.
- **Rote learning** stores one row per position met: the position's description and its backed-up value, with no features or weights.
- **Deliberately absent**: any reward column and any terminal-position row. The method gave game-ending positions no special value, which is the weakness discussed below.

## Where it matters in practice

### Signs a problem fits

- Decisions can be searched ahead with known rules, but leaf positions need a cheap approximate evaluation that can be improved from play.

### What you need to use it

- A simulator or rules that generate successor positions, a feature description of positions, and a way to play many self-play games.
- Some anchor that ties scores to true outcomes, such as rewards or a fixed terminal value.

### When not to trust it

- When nothing ties the learned scores to outcomes, so that they can drift to useless but consistent values (see limitations).

## Assumptions & limitations

- **Missing anchor**: TD learning makes a value function consistent with itself, but must also tie it to the true values, through rewards and discounting or a fixed terminal value. This program had no rewards and no special treatment of game-ending positions.
- **Constant solution**: the value function could become consistent by giving every position the same value, as the program's designer himself noted. The large fixed piece-advantage weight makes this less likely but does not forbid it, since the modifiable weights could be set to cancel it.
- **Observed degradation**: because learning was not constrained to useful evaluation functions, it could get worse with experience, and the designer saw this during long self-play training. He restored improvement by setting the weight of largest absolute value back to zero.
- **Two readings of that fix**: the designer saw it as jarring the program out of local optima (weight settings that are best only among nearby settings); the book suggests it may instead have jarred it out of evaluation functions that were consistent but unrelated to winning or losing.
- **Not master level**: the rote-learning version reached the level of a better-than-average novice, the generalization version approached better-than-average play, and the later version with signature tables was still below master level.
- **Relation to later work**: the book calls the generalization method the same in concept as the learning in [[14.1 TD-Gammon]].
