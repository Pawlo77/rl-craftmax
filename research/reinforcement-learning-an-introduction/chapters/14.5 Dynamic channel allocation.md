# Dynamic channel allocation (Sutton & Barto, Chapter 14, case study)

> [!abstract] TL;DR
> A cellular phone network must decide which radio channel each new call gets so that as few calls as possible are blocked; the case study treats this as a semi-Markov decision process (semi-MDP) and learns an afterstate value function with linear temporal-difference (TD) learning. The learned allocator blocked fewer calls than a fixed assignment and than the best heuristic dynamic method at every traffic level tried, with the gap shrinking as the system saturates.

## Problem

- **Setting**: a service area is split into cells, each with a base station handling its calls. The bandwidth is divided into channels (bands of frequencies), and one channel can carry many calls at once if the calls are far enough apart.
- **Channel reuse constraint**: the minimum distance at which two calls on the same channel do not interfere; every assignment must respect it.
- **Objective**: minimize blocked calls. A call is blocked (lost) when no channel is available for a new call or for a call handed off from one cell to another as the caller crosses a cell boundary.
- **Fixed versus dynamic assignment**: a fixed assignment method gives channels to cells permanently so the constraint can never be broken, even if every channel in every cell is busy. A dynamic assignment method makes all channels potentially available to all cells and assigns them as calls arrive, so cells with a burst of calls can receive more channels without raising blocking in quiet cells.
- **Why it is hard**: the choice for one call changes what is possible for later calls in neighboring cells, and arrivals, departures and handoffs are random. Three cells in a line, two channels, and neighbors that cannot share a channel show it: if the left cell uses channel 1 and the right cell uses channel 2, a new call in the middle cell is blocked; if both ends use channel 1, the middle cell can take channel 2.

## Conceptual framework

- **Semi-Markov decision process**: a decision problem in which decisions are triggered by events at irregular times instead of at fixed time steps. The elevator dispatching case study ([[14.4 Elevator dispatching]]) is formulated the same way; the value of a stretch of time between decisions is discounted by its length (see Math).
- **Afterstate**: the configuration right after the system's own action, before the environment responds. Defined in [[06 Temporal-difference learning]]; here the value function is learned over afterstates only.
- **Linear function approximation**: the value is a weighted sum of features of the configuration, as in [[09a Function approximation and linear methods]].

## Approach

1. **State**: two components.
   - The configuration of the whole system: for each cell, whether each channel is occupied or unoccupied there. A typical system with 49 cells and 70 channels has $70^{49}$ configurations, which rules out conventional dynamic programming ([[04 Dynamic programming]]).
   - The kind of event that caused the transition: call arrival, departure or handoff. It determines which actions are possible.
2. **Actions**:
   - Arrival: assign the call one of the free channels, or block it if none is free.
   - Departure (a caller hangs up): reassign the calls still in progress in that cell, one candidate action per ongoing call moved to the newly freed channel, to try to reach a better configuration.
3. **Reward and return**: the immediate reward is the number of calls in progress at that time, discounted continuously. Maximizing the expected return is the same as minimizing the expected discounted number of blocked calls over an infinite horizon.
4. **Afterstates**: every action leads deterministically to a known new configuration. The learned value function covers configurations only; to act, compute the configuration each action would produce, evaluate each with the value function and pick the action leading to the highest estimate.
5. **Features** for a configuration, all normalized to lie between $-1$ and $1$:
   - **Availability**, one per cell: how many additional calls the cell could accept without conflict if all other cells stayed frozen in the current configuration.
   - **Packing**, one per cell-channel pair: how many times that channel is in use within a four-cell radius of that cell.
6. **Learning**: the weights of the linear value function are updated online with a semi-Markov version of linear TD(0), after each decision.

### Results against baselines

- **Setup**: a simulated $7\times7$ array of cells with 70 channels; two calls may share a channel only if at least 3 cells apart. Calls arrive in each cell as a Poisson process (random arrivals at a given mean rate, which may differ by cell) and last a random, exponentially distributed time with a mean of three minutes.
- **Baselines**: fixed assignment (FA); and borrowing with directional channel locking (BDCL), the best dynamic method the study found in the literature, a heuristic that assigns channels to cells as FA does but lets a cell borrow from neighbors when needed, using a channel ordering to decide what to borrow and how to reassign calls within a cell.
- **Outcome**: tested at mean arrival rates of 150, 200 and 350 calls per hour and a case with different rates in different cells. The learned method (RL) blocked the fewest calls in every case, and learning was rapid: it was ahead soon after starting.
- **Approximate blocking** (read off the bar chart; the section prints no table):

| Traffic | FA | BDCL | RL |
|---------|----|------|----|
| 150 calls/hour | about 10% | about 2% | about 1% |
| 200 calls/hour | about 21% | about 14% | about 12% |
| 350 calls/hour | about 48% | about 46% | about 43% |
| Nonuniform | about 28% | about 12% | about 7% |

- **Saturation**: the differences shrink as the arrival rate grows, as expected, because a saturated system leaves few chances for a dynamic method to arrange favorable usage. Practice cares about the unsaturated range, since systems are built with enough capacity that more than 10% blocking is rare.
- **A second formulation**: another study of RL for this problem did not minimize blocking directly but assigned a cost to channel-use patterns by the distances between calls sharing a channel, favoring patterns where sharing calls are close. Its blocking was closely comparable to MAXAVAIL, a strong method that gives each new call the channel maximizing the number of channels available in the whole system, in a 49-cell, 70-channel simulation; the key point is that the learned policy runs on-line much more cheaply, whereas MAXAVAIL needs so much on-line computation that it is not feasible for large systems.

## Math

**Notation.** Symbols follow earlier notes; the return deviates by using continuous time.

| Symbol | Meaning |
|--------|---------|
| $R_t$ | immediate reward at time $t$: number of calls in progress then |
| $G_t$ | return, a continuous-time discounted integral of rewards |
| $\beta$ | continuous-time discount rate, $\beta>0$, playing the role of $\gamma$ |
| $\tau$ | integration variable: time elapsed after $t$ |
| $\hat v(s,\mathbf{w})$ | linear value estimate of afterstate configuration $s$ with weights $\mathbf{w}$ |
| $\mathbf{x}(s)$ | feature vector of $s$ (availability and packing features) |
| $\alpha$ | step size |
| $\Delta$ | time between a decision and the next one (formalized here) |
| $s, s'$ | afterstates chosen at one decision and at the next (formalized here) |

**Continuous-time discounted return:**

$$
G_t = \int_0^\infty e^{-\beta\tau} R_{t+\tau}\, d\tau
$$

- Calls in progress later in time count less, by the factor $e^{-\beta\tau}$, as $\gamma^k$ does for $k$ steps in a discrete-time return.

**Semi-Markov linear TD(0) update** (formalized here; the section names the method but prints no equation):

$$
\mathbf{w} \leftarrow \mathbf{w} + \alpha \Big[ \int_0^{\Delta} e^{-\beta\tau} R_{t+\tau}\, d\tau + e^{-\beta\Delta}\, \hat v(s',\mathbf{w}) - \hat v(s,\mathbf{w}) \Big]\, \mathbf{x}(s)
$$

- The bracket is the TD error: reward accumulated until the next decision, plus the discounted value of the next afterstate, minus the current estimate. The discount $e^{-\beta\Delta}$ depends on the elapsed time, which is what makes the update semi-Markov.
- For a linear $\hat v$ the gradient with respect to $\mathbf{w}$ is $\mathbf{x}(s)$ (see [[09a Function approximation and linear methods]]).

One row per candidate action at one decision: a call arrives in the second cell of a line of four cells with three channels; neighbors cannot share a channel, the first cell uses channel 1, the fourth uses channel 2, and the second and third are empty. Channels 2 and 3 are free for the new call (channel 1 is used by its neighbor). Illustrative rows; the section prints no data, and the values are invented. | candidate action | afterstate configuration | calls in progress | availability (cells 1 to 4) | $\hat v$ (illustrative) |
|------------------|--------------------------|-------------------|-----------------------------|--------------------------|
| assign channel 2 | `1 / 2 / - / 2` | 3 | (1, 1, 2, 2) | 4.1 |
| assign channel 3 | `1 / 3 / - / 2` | 3 | (1, 1, 1, 2) | 3.8 |

- **Selected action**: assign channel 2, the highest-valued afterstate. Blocking is possible only when no channel is free, so it is not a candidate here.

After assigning channel 2, cell 1 loses channels 1 and 2 (one left), cell 2 loses 2 and 1 (one left), cell 3 loses 2 (two left), cell 4 loses 2 (two left). After assigning channel 3, cell 3 loses 3 and 2 (one left), so the total is 5 against 6.
- **Column to symbol**: the configuration is the afterstate $s$; availability is part of $\mathbf{x}(s)$; the packing features are omitted because the toy line is shorter than the four-cell radius.
- **Absent**: the rest of the 49-cell system; a real row also carries the event type and, for the update, the elapsed time $\Delta$ to the next decision.

## Where it matters in practice

### Signs a problem fits

- Decisions come from random events at irregular times, each choice constrains later choices, and the quantity to optimize accumulates over time.
- The effect of an action on the configuration is known and deterministic, though the long-term payoff is not.

### What you need to use it

- **A simulator or live system** to learn from online.
- **Features** that summarize a configuration far too large to enumerate, here the availability and packing features.
- **Strong heuristic baselines** to compare against.

## Assumptions & limitations

- **Simulation only**: results come from simulated Poisson arrivals and exponential call durations, not from a deployed network.
- **Hand-built features**: performance depends on availability and packing features designed for this problem; the section does not say how sensitive results are to them.
- **Objective formulated indirectly**: the reward counts calls in progress, and maximizing its discounted return is the same as minimizing the expected discounted number of blocked calls; the second study's distance-based cost shows the objective can be formulated differently.
- **Asymptotic results only**: the plotted blocking is the learner's asymptotic performance; the speed of learning is described in words.
