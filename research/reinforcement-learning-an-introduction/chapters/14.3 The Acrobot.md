# The acrobot (Sutton & Barto, Chapter 14, case study)

> [!abstract] TL;DR
> The acrobot is a two-link robot with a motor at only one joint that must swing its tip up to a target height in minimum time. Sarsa($\lambda$) with tile-coded linear function approximation, run on a simulator as if it were a real robot with no model, learned an efficient swing-up policy in every run, typically about 75 steps long.

## Problem

- **Task**: control a two-link, underactuated robot (fewer actuators than joints), like a gymnast swinging on a high bar. The first joint (the hands on the bar) cannot exert torque; the second joint (bending at the waist) can.
- **Goal**: swing the tip (the "feet") above the first joint by an amount equal to one link length, in minimum time.
- **Difficulty**: the state is continuous in four dimensions, only three torques are available, and the first joint cannot be driven directly, so success needs long sequences of correct actions.
- **Setting**: on-line (learning while interacting) and model-free (no model of the dynamics is learned or used, [[01 Introduction]]). The simulator existed but the agent could not use it in any way; training and interaction were exactly as with a physical acrobot.

## Conceptual framework

- **State** $S_t$: four continuous variables, the two joint angles $\theta_1, \theta_2$ and the two joint angular velocities $\dot\theta_1, \dot\theta_2$. $\theta_1$ is measured from the downward vertical and $\theta_2$ from the line of the first link.
- **Actions** $A_t$: the torque $\tau$ at the second joint, one of three: $+1$, $-1$ or $0$ (positive fixed magnitude, negative of the same magnitude, none).
- **Reward** $R_{t+1} = -1$ on every time step until the goal is reached, which ends the episode. There is no discounting, $\gamma = 1$.
- **Optimal value**: the book calls $v_*(s)$ the minimum time to the goal (an integer number of steps); with $-1$ per step the value is minus that count (derived here). Returns and episodes are defined in [[03a MDP setting and returns]].
- **Episodes**: each begins with both links hanging straight down and at rest; after the goal is reached the acrobot is reset to that position. The goal was always reached eventually.

## Approach

1. **Learner**: Sarsa($\lambda$) with linear function approximation, tile coding and replacing traces, the algorithm of [[09b Control with approximation, bootstrapping]] (tile coding itself: [[09a Function approximation and linear methods]]; traces: [[07b Eligibility-trace control and off-policy]]).
   - With three discrete actions it is natural to use a separate set of tilings for each action.
2. **State representation**: a naive, direct one, the four variables $\theta_1, \dot\theta_1, \theta_2, \dot\theta_2$.
   - A cleverer design would use the angular position and velocity of the center of mass and of the second link, which might simplify the solution and generalize more broadly; this was only a test problem, so it was not tried.
   - The state space is a bounded four-dimensional rectangle: the angular velocities are limited to the ranges given in Math, and the angles cover one full turn (the text calls them restricted to $[0, 2\pi]$ while the simulation description says joint positions were unconstrained, so only the full-turn range is stated here).
3. **Tilings**: each of the four dimensions was divided into six equal intervals. A seventh interval was added for the two angular velocities so that tilings could be offset by a random fraction of an interval in every dimension.
   - Of 48 tilings, 12 slice along all four dimensions ($6 \times 7 \times 6 \times 7 = 1764$ tiles each), 12 along three dimensions (3 tilings for each of the 4 sets of three), 12 along two (2 for each of the 6 pairs) and 12 along one (3 for each of the 4 dimensions).
   - This gives approximately 25,000 tiles per action, few enough that hashing (folding a huge tile set into a smaller table) was not needed. Formalized here: counting the tiles of each kind adds to about 25,030.
4. **Parameters**: $\alpha = 0.2/48$ (the step size divided by the number of tilings), $\lambda = 0.9$, $\varepsilon = 0$ and initial weights $\mathbf{w}_0 = \mathbf{0}$.
5. **Exploration by optimism**: the policy is purely greedy ($\varepsilon = 0$), because one exploratory action can spoil a long sequence of correct actions.
   - Instead, initial action values of 0 are optimistic, since every true value is negative. The agent is continually disappointed by the rewards it actually receives and keeps trying new things (the mechanism of [[02 Multi-armed bandits]] and the mountain-car example of [[09b Control with approximation, bootstrapping]]).

## Math

**Notation.**

| Symbol | Meaning |
|--------|---------|
| $\theta_1, \theta_2$ | joint angles; dots denote angular velocity, two dots angular acceleration |
| $\tau$ | torque at the second joint, the action, in $\{+1, -1, 0\}$ |
| $m_i, l_i, l_{ci}, I_i$ | mass, length, distance to the center of mass and moment of inertia of link $i$ |
| $g$ | gravity |
| $d_1, d_2, \phi_1, \phi_2$ | intermediate terms of the dynamics |
| $\alpha, \lambda, \varepsilon, \gamma$ | step size, trace decay, exploration probability, discount (as in [[09b Control with approximation, bootstrapping]]) |
| $\mathbf{w}$ | weight vector of the linear action-value function |

**Equations of motion of the simulated acrobot:**

$$
\ddot\theta_1 = -d_1^{-1}\left(d_2 \ddot\theta_2 + \phi_1\right)
$$

$$
\ddot\theta_2 = \left(m_2 l_{c2}^2 + I_2 - \frac{d_2^2}{d_1}\right)^{-1}\left(\tau + \frac{d_2}{d_1}\phi_1 - m_2 l_1 l_{c2}\dot\theta_1^2 \sin\theta_2 - \phi_2\right)
$$

$$
d_1 = m_1 l_{c1}^2 + m_2\left(l_1^2 + l_{c2}^2 + 2 l_1 l_{c2}\cos\theta_2\right) + I_1 + I_2, \qquad d_2 = m_2\left(l_{c2}^2 + l_1 l_{c2}\cos\theta_2\right) + I_2
$$

$$
\phi_1 = -m_2 l_1 l_{c2}\dot\theta_2^2 \sin\theta_2 - 2 m_2 l_1 l_{c2}\dot\theta_2\dot\theta_1 \sin\theta_2 + (m_1 l_{c1} + m_2 l_1) g \cos(\theta_1 - \pi/2) + \phi_2
$$

$$
\phi_2 = m_2 l_{c2}\, g \cos(\theta_1 + \theta_2 - \pi/2)
$$

- These give the angular accelerations from the state and the torque; the agent never sees them.
- **Constants**: $m_1 = m_2 = 1$, $l_1 = l_2 = 1$, $l_{c1} = l_{c2} = 0.5$, $I_1 = I_2 = 1$, $g = 9.8$.
- **Simulation**: a time step of 0.05 seconds, with an action chosen after every four steps (so every 0.2 seconds). Velocities are limited to $\dot\theta_1 \in [-4\pi, 4\pi]$ and $\dot\theta_2 \in [-9\pi, 9\pi]$.

> [!example] Goal test
> Formalized here: the book states the goal in words only. With $\theta_1$ from the downward vertical and $l_1 = l_2 = 1$, the tip height above the first joint is $-\cos\theta_1 - \cos(\theta_1 + \theta_2)$, and the goal is reached when it is at least 1. Hanging at rest ($\theta_1 = \theta_2 = 0$) gives $-2$, the lowest possible.

## Results

- **Single episodes** were sometimes extremely long. The acrobot usually spun repeatedly at the second joint while the first joint stayed near vertical down; this always ended eventually because the action values were driven lower.
- **All runs** ended with an efficient policy, usually about 75 steps per episode. The learning curves are steps per episode on a log scale over 500 episodes, for a typical single run, the median of 10 runs and a smoothed average of 10 runs.
- **A typical final solution**: first the acrobot pumps back and forth several times symmetrically, with the second link always down. Once enough energy has been added, the second link is swung upright and "stabbed" to the goal height.

## Dataset example

| $t$ | $\theta_1$ | $\dot\theta_1$ | $\theta_2$ | $\dot\theta_2$ | $A_t = \tau$ | $R_{t+1}$ | tip height of $S_t$ | next state in goal? |
|-----|------------|----------------|------------|----------------|--------------|-----------|---------------------|---------------------|
| 0 (start) | 0.00 | 0.0 | 0.00 | 0.0 | $+1$ | $-1$ | $-2.00$ | no |
| 20 | 0.90 | 1.5 | 0.00 | 0.4 | $-1$ | $-1$ | $-1.24$ | no |
| 50 | 1.30 | 1.2 | 0.00 | 0.0 | $0$ | $-1$ | $-0.53$ | no |
| 74 (last) | 1.60 | 1.0 | 0.80 | 3.0 | $+1$ | $-1$ | $0.77$ | yes (height about 1.22) |

- **Column to symbol**: the four angle columns are $S_t$, the torque is $A_t$, and $R_{t+1} = -1$ on every row; the four continuous values are what tile coding turns into binary features.
- **Derived**: the return from $t$ is minus the number of remaining steps (here 75 steps in the episode, so $G_0 = -75$ with $\gamma = 1$); the next-state height on the last row follows from $\theta_1 + 0.2\,\dot\theta_1 = 1.8$ and $\theta_2 + 0.2\,\dot\theta_2 = 1.4$ (ignoring the velocity change within the action interval).
- **Absent**: tile indices, weights, action values and the trace vector.

## Where it matters in practice

### Signs a problem fits

- A continuous-state control task with a small discrete action set and a clear time-to-goal objective, where a simulator or the real system can be run for many episodes.

### What you need to use it

- **Reward**: $-1$ per step, so that minimizing time equals maximizing return, with an episode end at the goal.
- **Representation**: tilings that slice the state along one, two, three and all four dimensions; each step touches one tile per tiling, so the cost scales with the number of tilings rather than the 25,000 tiles per action.
- **Exploration**: optimistic initial values in place of $\varepsilon$-greedy, when one random action can ruin a long correct sequence.

### When not to trust it

- Formalized here: optimism needs initial values above every true value; with the $-1$ rewards, 0 is, but with rewards that can be positive it would not be.

## Assumptions & limitations

- **Naive state representation**: the direct angles and velocities were used rather than a representation that might generalize better; the book leaves open how much that would help.
- **Hand-chosen tilings**: the number, width and kind of tilings (and the random offsets) are design choices with no systematic search in this task.
- **One task, one setting**: the acrobot was simulated (treated as if real), and the result is a set of learning curves from this single design, with no comparison to other representations or methods.
- **Very long early episodes**: spinning at the second joint can last many steps before the values drop; the method relies on that always ending.
