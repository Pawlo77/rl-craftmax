# analysis

## Responsibility

- Phase 4 analysis of finished runs: load the exported tables, per-method training analysis, obstacles, cases ([[2026-10-20-craftax-training-analysis]]) and the method comparison ([[2026-10-20-craftax-comparison-and-results]]).
- Filled by the training analysis and comparison tasks; so far the loaders, the literature table, the obstacle detectors, the hard-scenario summaries and the comparison tables.
- Training-analysis cases (TA3): the case finder, its replay export and the case facts.
- Training-analysis CLI (TA5): runs the hard summaries, obstacle detectors and cases of every (budget, method) and logs them to MLflow.
- Comparison CLI (C6): runs every table and figure of the comparison from the export, writes the report files and logs one MLflow run.
- Hand-off (TA6, TA7): the 1M outputs are written up as one note per method under `knowledge/results/` (summary at the top, quoted by the report and the comparison plan), and `cases.csv` carries the `video` flag the video and the Hugging Face release read ([[2026-10-20-craftax-visualisation-production]], [[2026-10-20-craftax-huggingface-release]]).
- Final results note (C7): [[Final results]] writes the 1M comparison out as Markdown (T1 of both blocks, PoI and Holm p, reproduction check, T2, ablations, tuning optimism, T3, T6, T7, hardware context, figure index) from `outputs/results/tables/*.csv`; its "Interpretation (decision trees)" section stays a placeholder until the distillation run, and its 1B sections stay pending (R75).

## Public surface

- `load_phase(phase_dir)`, `load_phases(phases, root, skip_missing=, tables=)` (`tables=("runs",)` leaves the big tables empty): the export tables as `{"runs", "curves", "eval_episodes"}` frames; `load_phases` keeps a run of two phases once, from the first phase listing it, and warns when the dropped copy differs; pass `final-*` before tuning phases.
- `select(frames, method=, config_ref=, budget=, phase=, pool=False)`: the matching runs and their rows in every frame; `phase` matches the `phases` tag (`in_phase(runs, phase)` is its mask). It raises when the result mixes `config_ref` values of a method and no `config_ref` or `pool=True` is given.
- `units(frames)`: each (`method`, `config_ref`) with its own frames.
- `BASE_CONTROL` (non-combo method -> control), `CONTROLS`, `base_control(row)`, `pair_of(row)`: the control a run is compared with; a combo run's comes from its own pair.
- `final_checkpoint(episodes, run=None)`: the last checkpoint's eval episodes per run.
- `load_literature(path=)`: the published rows of blocks A, A2 and D of [[Existing Implementations]] from `configs/literature/existing_implementations.csv` (columns `block, implementation, note, env, observation, budget, protocol, score_pct, spread, spread_kind, seeds, score_text`; `note` is the linked note's file stem; `protocol` is the block's (A: training-episode return, A2: separate evaluation of the trained policy), `n.r.` where the row's source note says the protocol is unstated (PPO-GTrXL, PQN-RNN, SimBa, EASimulus), and per row in block D from the notes). `LITERATURE_CSV` and `LITERATURE_COLUMNS` are the path and the column list.
- `comparable_rows(score_kind, budget)`: the like-for-like block (`COMPARABLE_BLOCKS`): `("training", "1b")` is A, `("training", "1m")` is D, `("stochastic", "1b")` is A2; any other pair raises `ValueError`.
- `MissingPhaseError` (a `FileNotFoundError` naming the phases), `SchemaError`, `FINAL_PHASES`, `METRICS_ROOT`, `UNIT_COLUMNS`.
- `detect_all(frames, method, budget, config_ref="tuned")`: one `Obstacle(name, run, start, end, evidence, status)` per run and detector of `DETECTORS[method]`; `status` is `detected`, `absent`, `not logged`, `needs replay (evaluation Task 6)`, `needs eval actions`, `not applicable` or `uninformative at <budget>`.
- `DETECTORS` (registry method -> `Detector` list), built from `shared_detectors()`, `count_bonus_detectors()`, `sil_detectors()`, `skill_detectors()`, `dyna_detectors()`; a `Detector` declares `REQUIRED_METRICS`, `BASE_METRICS`, optional `inputs`, informative `budgets` and owner `methods`.
- `ALIASES`: plan metric name -> stored names in order (contracts section 5; the comparison figures import it).
- `table_rows(obstacles, budget)`, `obstacles_table(rows)`: the obstacles table with exactly `TABLE_COLUMNS` of the plan template.
- `drawdown_floor(budget, c)`: the R92 drawdown floor of a smoothed score curve (1 point at 1B, else `max(0.1, 0.25 x` best)); the detectors and comparison T3 share it.
- `repeated_cycle(actions)` -> `Cycle(period, start, length)`: the shortest action period repeated over >= 50 steps; `eval_actions(run_dir, run_id, update, mode)` reads an eval file into the `eval_actions` input.
- `floor_reach(episodes, mode="stochastic", n=10000, floors=9)`: per unit and floor, the share of final eval episodes with `max_floor >= f` (`rate`, the mean over seeds of each seed's share, fractions) with the bootstrap interval `lo`, `hi` over seeds, `reached_seeds` and `status` (`never`, `rare` below `RARE_RATE` = 5%, `common`); every summary records its basis in `mode` and, where it has one, `scope` (`final` = each run's last checkpoint, `all`, `checkpoint`).
- `achievement_status(episodes, curves=None, mode=)`: per unit and achievement, `final_rate`, `best_rate` and `best_update` over the checkpoints, `seeds_ever` of `n_seeds` (any eval, or training given `curves`), `eval_seeds`, `train_seeds`, `train_logged` and `status` (`never`, `never in eval`, `rare`, `common`), in tier, floor, value order. `ACHIEVEMENTS` (name -> `Achievement(tier, floor)`, value order) is the tier and floor table.
- `death_causes(episodes, mode=)`: cause-of-death shares per unit, as one row set per eval checkpoint (`scope` `checkpoint`) and one over each run's own last checkpoint (`scope` `final`); a death with an empty cause is `not recorded` (the real `unknown` cause stays apart); a set without deaths has one `(no deaths)` row with NaN share.
- `stall_table(episodes, mode=, final=True)`: one row per stall (frames, floor, `ending`, `ended_by`, `started_by`); `stall_stats(episodes, mode=, n=, final=)`: per unit stalls per episode (interval over seeds), median length, escape rate and `start_floor/<f>` counts; `stall_starts(table)`: where stalls start (floor, unlock); `stall_ccdf(table)`: the length CCDF.
- `plot_floor_reach`, `plot_achievement_status`, `plot_death_causes`, `plot_stall_lengths` (table, `out_dir`, `theme="report"`) -> the PNG path (`floor_reach.png`, `achievement_status.png`, `death_causes_over_training.png`, `stall_lengths.png`), the shared `charts.Theme` (report light at 170 mm, 300 dpi; `theme="video"` dark, name gets `_video`), legends outside the axes; one budget per plot, a unit per line or panel.
- Core figures (`figures`; `FIGURES` maps F1-F5, F18-F20 to their functions, `NAMES` to file stems): `plot_curves_score` (F1), `plot_aggregate` (F2), `plot_aggregate_poi` (F2 and F3 side by side, the report's F2), `plot_poi_matrix` (F3), `plot_seed_spread` (F4), `plot_success_heatmap` (F5), `plot_sensitivity` (F18), `plot_stability` (F19), `plot_hardware` (F20), each `(frames, out_dir, theme="report"|"video", ...) -> Figure` writing `<stem>.png` (PNG only; `<stem>_video.png` for the video). Keyword `table=` (and `ablation=`, `per_run=`, `literature=`) takes an already computed table, `n_boot=` and `seed=` set the bootstrap. Report figures take `width="column"` (80 mm) or `"double"` (170 mm, files `<stem>_double.*`; F1 then is one panel per budget), fonts 7 pt or more; video figures 1920 x 1080; colours are `charts.METHOD_COLORS` (controls dashed grey with markers, ablations dotted and hollow, label `<method> (<config_ref>)`).
- In-game figures (`figures_game`; `GAME_FIGURES` maps F6-F17, `GAME_NAMES` the stems; same signature, suffixes and widths as the core figures): `race` (F6, `race_steps` and `race_wall`; `upto=<env steps>` draws only the first unlocks before that step on the full race's axes and `out_dir=None` writes no file, for the race GIF), `plot_race`, `plot_order_graph` and `plot_order_graphs` (`order_<method>`), `plot_order_agreement` (F7), `plot_funnel` and `plot_funnel_training` (F8), `plot_deaths` and `plot_stalls` (F9), `plot_splits` (F10), `plot_coverage` (F11), `plot_survival` (F12), `plot_combat` (F13), `plot_actions` (F14), `plot_resources` (F15), `plot_advanced` (F16), `plot_radar` and `plot_radars` (F17, `radar_<budget>`). Tables behind them: `order_graph` (nodes, edges after `transitive_reduction`), `kendall_permutation`, `order_agreement`, `funnel_shares`, `split_table`, `radar_table`. Order agreement leaves the cells of two non-control methods of different blocks blank. Race medians and winners are `compare.race_table`'s (`upto` only masks later unlocks to +inf, never a second rule; `compare.first_unlocks` gives the per-run values). Per-method statistics are the median over seeds of each seed's episode median (shares: the mean) with an `evaluation.stats` bootstrap. A family a method never logged reads "not logged" (R78: PPO and PPO-RNN in F6, F8 over training, F14 training entropy, F16); an eval column no replay filled reads "not recorded".
- LaTeX export (`latex`, contracts section 7): `write_tables(frames, out_dir=report/tables)` renders T1 (`main_<budget>.tex`, also `main.tex` as the 1M table; `main_vs_1m.tex` for PoI and Holm p), T2 (`literature.tex`, with our CI and the reproduction-gate status, gap and h per control), T5 (`stability_hardware.tex`, laptop heading carries the R97 note, SPS never ranked) and T6 (`game_summary_<budget>.tex`, also `game_summary.tex` as the 1M table) as `tabular` with booktabs rules, escaped names and the best value of each column bold within a benchmark and block; `write_numbers(path=report/numbers.tex, frames)` writes one `\newcommand` per number named `<quantity><Budget><Method>[<Ref>][<Control>]` in letters only (`MACRO_NAMES`, `macro()`; `Dagger` ends a `dagger` complexity variant); `copy_figures(results_dir, report/figures)` copies the report PNGs (no `_video`) and deletes the `<stem>.pdf` of each. A budget without runs gets no table and no macro (no `final-1b` yet, R75, R86); the 1M `outputs/interpretation/1m/complexity.csv` is required (the error names interpretation Task 6), the 1B one is skipped when missing; `undefined_macros()` lists macros of this family that `report/report.tex` uses and `numbers.tex` lacks; `write_numbers` runs it against the existing report and raises (after writing the file) when the list is not empty. `<` prints as `$<$`, negatives as `$-$`. Complexity macros add the `NoMemory`/`Dagger` tails and the R106 quantities (`majority`, `gain*`, `peakValLeaves`, `group*`, `spearmanScoreFidTwoFiftySix`); an unknown variant raises a `ValueError` naming it; a column missing from an older `complexity.csv` just gives no macro. `-` and `<` in macro text are `\ensuremath`.
- Analysis-angle figures (`figures_angles`; `ANGLE_FIGURES` maps F21-F28, `NAMES` the stems; same signature, suffixes and widths, PNG only through `figures._save`), each answering the question in its title: `plot_greedy_gap` (F21 `greedy_gap`: greedy minus stochastic eval score per checkpoint, table `greedy_gap`), `plot_gatekeepers` (F22 `gatekeepers`: lift in later unlocks with each mid-share achievement against without it, among episodes alive at the method's median unlock step, table `gatekeepers`), `plot_seed_fate` (F23 `seed_fate`: Spearman of the seeds' checkpoint score and final score, table `seed_fate`, the 5% critical band), `plot_ablation_effects` (F24 `ablation_effects`: forest of `ablation_table`, `table=`, with a cross for the difference to the fresh tuned seeds where some were reused from tuning), `plot_tuning_optimism` (F25 `tuning_optimism`: tuning mean against fresh final mean, `table=` from `tuning_optimism`), `plot_episode_spread` (F26 `episode_spread`: achievements-per-episode distribution and achievements by length bin), `plot_distil_score` (F27 `distil_score`: score against 256-leaf fidelity with the pooled R106 Spearman and `within_rho`, the mean within-method one) and `plot_distil_features` (F28 `distil_features`: permutation importance per input and method); F27 and F28 take `interpretation=` (default `outputs/interpretation`) and read only finished policy folders (`<budget>/<method>/<run_id>/complexity.json`, then `importance_base.csv`), naming each method short of its tuned runs as pending.
- Comparison CLI (`results`, C6): `python -m wut_murl_craftax.analysis.results --phases final-1m [final-1b combo-1m combo-1b] --tuning tune-coarse tune-fine --out outputs/results --tracking-uri sqlite:///<db>?timeout=300 [--report-dir report] [--metrics-root outputs/metrics] [--complexity-root outputs/interpretation] [--no-complexity] [--no-log] [--force] [--n-boot N] [--n-perm N] [--seed S]` = `run_comparison(ResultsOptions)` -> `ResultsSummary(done, skipped, failed_gates, problems, run_id)`. Phases never exported are skipped (R86), a missing tuning phase stops the run. Out: `<out>/tables/<stem>.csv` (`main`, `literature`, `stability`, `stability_runs`, `hardware`, `game_summary`, `sensitivity`, `ablation`, `tuning_optimism`, `race`, `poi_matrix`, `reproduction_gate`) and the `.tex` of `latex.write_tables`, `<out>/figures/<stem>[_double|_video].png` for every figure of `FIGURES`, `GAME_FIGURES` and `ANGLE_FIGURES` (with `plot_order_graphs` and `plot_radars` for F7 and F17) and the distillation's `fidelity_vs_leaves_<budget>`; `<report-dir>/tables/*.tex`, `numbers.tex`, `figures/*.png` (no `_video`; a `*.pdf` of an earlier run is deleted from `<out>/figures` and, per copied figure, from the report folder). The MLflow run `comparison-final` of experiment `analysis` holds `tables` and `figures` (tags `analysis/kind`, `analysis/phases`, `analysis/tuning`). `--no-complexity` leaves out the complexity macros (it writes `numbers.partial.tex` instead if `numbers.tex` already holds them), still checks the other report macros, and deletes stale fidelity figures instead of copying them. F20 is drawn for 1M only (a warning says so when 1B exists).
- Comparison tables (`compare`), each a DataFrame with the listed column constant; `n_boot` and `seed` set the bootstrap (protocol: 10,000):
  - `main_table(frames)` (T1, `main_columns()`): per (benchmark, block, method) of the tuned runs: seeds, mean +- s.e., mean CI, IQM [CI] at 1M or median [CI] and t interval at 1B, final-checkpoint eval means, and per control `poi_<c>`, `poi_lo_<c>`, `poi_hi_<c>`, `p_<c>`, `p_holm_<c>` (1M) or `diff_<c>` with its Welch t interval (1B); `indicative` marks 1B.
  - `poi_matrix(frames)` (F3, `POI_COLUMNS`): PoI with CI between every two members of one block at 1M.
  - `ablation_table(frames)` (`ABLATION_COLUMNS`, R77): each ablation of a final phase (`simhash`, `single-buffer`, `random-top`, `monte-carlo`, `no-flags`, `kappa0`) against its method's tuned runs: difference of means with a bootstrap CI (1M) or Welch t interval (1B), and at 1M PoI and Holm p within the block.
  - `reproduction_gate(frames, published=, published_hash=)` (`GATE_COLUMNS`): per control and benchmark with runs, over the runs of the published config hash (`reproduction.published_config_hashes`): `pass` or `fail` with gap and `h` of `reproduction.band`, `too few seeds`, `no published spread`, `published config not run`, or the PQN-RNN 1M reference-code note (`REFERENCE_CODE`); never raises.
  - `literature_table(frames)` (T2, `LITERATURE_TABLE_COLUMNS`): per comparable (score kind, benchmark) our rows (mean, s.e., CI, gate on training control rows), then the one literature block; `ours_above`, `ours_within`, `ours_below` only on rows of our protocol (`protocol_match`: `same`, `different protocol`, or `protocol not reported` for `n.r.`), `indicative` on 1B groups.
  - `stability_table` (T3, `STABILITY_COLUMNS`), `hardware_table` (T4 per profile, `HARDWARE_COLUMNS`, laptop rows carry `CONTEXT_NOTE`), `race_table` (`RACE_COLUMNS`, `wall_note`), `game_summary_table` (T6, `GAME_COLUMNS`, `wall_note`), `sensitivity_table` (T7 per tuning phase, `SENSITIVITY_TABLE_COLUMNS`; raises when no run of a phase is tagged `best`); T2, T3, T4 and T6 carry `indicative`.
  - `tuning_optimism(frames)` (`TUNING_OPTIMISM_COLUMNS`, R101, R102): per tuned unit the 3-seed tuning mean of its config hash (tune-fine, else tune-coarse, `TUNING_ORDER`), the mean of its fresh final seeds (not reused from tuning, `fresh_seeds`) and `optimism` = tuning - fresh; NaN with an `n/a` `optimism_note` when the config was selected on all its final seeds (the controls), has fewer than `MIN_FRESH` = 5 fresh seeds or was never tuned.
  - `run_stability(frames)` (`RUN_STABILITY_COLUMNS`): the per-run part of T3 (deepest drawdown, any drop, collapse per tuned run with a score curve), which `stability_table` aggregates; `budgets(runs)`, `tuned(runs)` and `members(runs)` are the tables' own budget walk, tuned filter and (block, method, role) rows, public for the figures.
  - `block_of(method, combo_pair)`: `skills` for `SKILL_METHODS` (select_pair's) and a combo whose own pair holds one, else `main`; `BLOCKS`.
- `find_cases(frames, method, budget, config_ref="tuned", mode="stochastic")`: the case episodes of one unit as `cases.csv` rows (`CASE_COLUMNS`: contracts section 4, then `env_steps`, `length`, `detail`); kinds `stall`, `deep_floor`, `rare_unlock`, `death`; `id` `<budget>-<method>-<kind>-<n>`, an ablation `<budget>-<method>-<config_ref>-<kind>-<n>`.
- `export_case(case, out_dir, run=None, *, tracking_uri=, root="outputs", overlay_kw=)`: replays one case and returns it with `rollout`, `master`, `gif` and `overlay` filled (paths relative to `root`); `run` is an `EvalRun` (shared compiles), a run directory, or looked up by `run_dirs`.
- `describe_case(case, run=None, *, tracking_uri=)`: the write-up facts of a case from one replay: floor, stats and inventory at `start` and `peak`, action counts in the window and the episode, coverage gained per floor, the 50 actions before the peak, `combat_damage`, `close_calls` (the `episode_records` rule, so a whole-episode window equals the record's column) and lowest health in the window.
- `python -m wut_murl_craftax.analysis.training --phases final-1m combo-1m [final-1b combo-1b] --method all|<names> --out outputs/analysis --tracking-uri sqlite:///<db>?timeout=300 [--metrics-root outputs/metrics] [--skip-missing] [--force] [--no-log] [--log-masters]` = `analyse_training(frames, methods=, out=, tracking_uri=, metrics_root=, phases=, log=, force=, log_skip=)` -> `TrainingSummary(done, skipped, failed)`: per budget and method the folder `<out>/<budget>/<method>/` and MLflow run `training-analysis-<budget>-<method>` (experiment `analysis`, `orchestration.tracking.ANALYSIS_EXPERIMENT`).
- `replay_frames(runs, finals, root)`: the optional `skill_ends` and `eval_inventory` frames of the runs from `<root>/<run_id>/{skill_ends,inventory}_<update>_stochastic.parquet` (contract section 10); a run counts only when its final checkpoint has the file.
- `write_cases(cases, root)`: `analysis/<budget>/cases.csv` (the passed methods' rows replaced, the others kept) and `analysis/<budget>/<method>/cases.csv`; `run_dirs(run_ids, tracking_uri)`: artifact directories from a SQLite store, read-only.

## Modules

One line each; signatures and details: [[Modules]].

- `cases`: case episodes per unit from the `hard` tables, their replay export (rollout, master, GIF, internals clip) and their facts.
- `compare`: the comparison's result tables (T1-T4, T6, T7, the PoI matrix, the ablation table, tuning optimism) and the reproduction gate.
- `figures`: the core comparison figures F1-F5 and F18-F20 for the report, the Space and the videos.
- `latex`: the report's booktabs tables, number macros and the report's figure PNGs.
- `figures_angles`: the analysis-angle figures F21-F28 (greedy gap, gatekeepers, seed fate, ablation forest, tuning optimism, episode spread, distillation score and inputs).
- `results`: the CLI of the comparison: tables, figures F1-F28 in every theme and width, the report files, resume, MLflow logging.
- `figures_game`: the in-game figures F6-F17 (race, order graphs, funnel, deaths and stalls, splits, coverage, survival, combat, actions, resources, advanced use, radars).
- `hard`: floor reach, achievement status, cause of death and stall summaries per unit, and their plots; the comparison figures (F9) import the death and stall functions.
- `literature`: the published scores of blocks A, A2 and D of [[Existing Implementations]] and the like-for-like block of each of our score kinds.
- `load`: loaders, schema checks, run selectors and base controls over the export tables of [[evaluation]].
- `training`: the CLI of the training analysis: files per (budget, method), the detector inputs from eval and replay files, MLflow logging, resume.
- `obstacles`: the 10 shared and 23 method obstacle detectors, their registry and the obstacles table.

## Data flow

- In: the export tables of [[evaluation]] under `outputs/metrics/<phase>/` (`runs`, `curves`, `eval_episodes` parquet; column contract in the Phase 4 contracts); eval files and checkpoints through [[visualisation]]; `configs/literature/existing_implementations.csv` (rows copied from [[Existing Implementations]]).
- Detectors read `curves` (stored names, `ALIASES`), `eval_episodes`, the base control's tuned runs of the same frames (one pool per method, seed medians; a control has one pool per other control, a combo run its pair base), and the optional frames below.
- Optional input frames of `detect_all` (a missing one reads `needs eval actions` or `needs replay (evaluation Task 6)`; contracts "Replay inputs for training analysis"):

| Frame | Column | Type | Meaning | Source |
|---|---|---|---|---|
| `eval_actions` | `run_id`, `update`, `mode`, `eval_seed` | str, int, str, int | the eval episode | `eval_actions(run_dir, ...)` from `eval/<mode>/<update>.npz` |
| `eval_actions` | `actions` | int array | the episode's actions, padding cut at `length` | eval file |
| `skill_ends` | `run_id`, `update`, `env_steps`, `mode`, `eval_seed` | str, int, int64, str, int | the eval episode and checkpoint | replay |
| `skill_ends` | `start`, `end` | int | episode steps where the skill started and ended | eval `extras/skill`, `extras/steps_in_skill` (no replay) |
| `skill_ends` | `skill` | str | `skills.SKILLS` name | eval `extras/skill` |
| `skill_ends` | `key` | int64 | `smdp.top_key` table row at the decision (`low_flags` and granularity as the run's config) | replay |
| `skill_ends` | `reason` | str | `skills.REASONS` name of the end (`success`, `failure`, `timeout`, `episode_end`, `floor_change`, `low_stat`) | replay |
| `skill_ends` | `pair_count` | int | Dyna-Q only: real outcomes of (`key`, `skill`) in the checkpoint's model, `count` of `eval/dyna_model_graph.parquet` (0 if absent) | model graph of the checkpoint |
| `eval_inventory` | `run_id`, `update`, `mode`, `eval_seed` | str, int, str, int | the eval episode | replay |
| `eval_inventory` | `steps` | int | episode steps | replay |
| `eval_inventory` | `capped_steps` | int | steps with at least one material at or above its `progress_key.CAPS` cap | replay |
- The training CLI reads the export tables of the phases (`load_phases`, all of them, so the base controls stay in view), then per budget and method: `hard` tables and plots of all its units, `detect_all` per unit with the optional inputs of that unit's runs (`eval_actions` of the final stochastic eval file, found through `run_dirs`; `replay_frames`), `find_cases` per unit, then `export_case` and `describe_case` per case with one `EvalRun` per run. Folder `<out>/<budget>/<method>/`: `hard/*.csv` (`floor_reach`, `achievement_status`, `death_causes`, `stalls`, `stall_stats`, `stall_starts`, `stall_ccdf`), `plots/*.png`, `obstacles.md` (a section and table per unit, tuned first) and `obstacles.csv` (a row per run and detector), `cases.csv`, `cases/<id>.json` (`describe_case` facts), `rollouts/`, `masters/`, `gifs/`, `overlays/`, markers `.complete` and `.logged`; the budget table `<out>/<budget>/cases.csv` and the flat `outputs/visualisation/runs/case-<id>.npz` as in contracts section 4.
- Cases replay eval files through [[visualisation]] (`as_rollout`, `render_master`, `cuts.gif`, `render_overlay`, `stored_episode`) and read state facts with `episode_records.trace_of` and `coverage.update_seen`.
- Case files (`export_case`, `out_dir` = `outputs/analysis/<budget>/<method>/`): `rollouts/case-<id>.npz`, `masters/case-<id>.mkv` (whole episode, frame = step), `gifs/<id>.gif`, stall `overlays/<id>.mp4`; the rollout is copied to `outputs/visualisation/runs/case-<id>.npz` (flat, for the video `runs/*.npz` glob), and that copy is the `rollout` column. A `cases.csv` consumer takes the 16 px master from the `master` column, or uses `Path(rollout).stem` with `--masters-dir`; a row's `rollout` path is never passed to `cuts.cut_kept` as is (it expects a stem).
- The comparison CLI loads the final phases in full (`load_phases`, `skip_missing`) and the tuning phases as `runs` only (`tables=("runs",)`, their curves are tens of millions of rows): `sensitivity_table` and F18 read the tuning phases on their own (`best` needs it), `tuning_optimism` a final-then-tuning frame. The tables are rebuilt and their CSV rewritten on every run (seconds; mixed-type columns rule out a parquet cache); each figure id and the logging is a stage with a marker holding an input fingerprint (export files, options, published scores, literature CSV and a hash of the `analysis`, `evaluation` and `charts` sources) under `<out>/.stages`; F27 and F28 also key on the stat of every finished policy summary (a live distillation adds policies without touching the export); the log stage also keys on the tracking URI and checks the run still exists; a rerun redoes only stages without a current marker, so it is idempotent (`--force` redoes all). A failing reproduction gate is listed in `ResultsSummary.failed_gates` and logged, never fatal; a report macro that `numbers.tex` lacks is written, logged and exits 1.
- The comparison tables read `runs` (final score, eval scores, hardware columns, `config_json` for combo pairs and sensitivity), `curves` (`train/score_pct`, `first_unlock/*`, `first_unlock_wall/*`), final-checkpoint stochastic `eval_episodes`, `configs/reference/published_scores.yaml` and the literature CSV.
- Out: `outputs/analysis/<budget>/`, `outputs/results/`, MLflow experiment `analysis`.
- Hand-off at 1M (1B pending, R75; `final-1b` and `combo-1b` not run):
  - Results notes, one per registry method, each opening with a 5-bullet summary (score and floors, achievements, deaths, stalls, obstacles) that [[2026-10-20-craftax-report]] (Discussion) and [[2026-10-20-craftax-comparison-and-results]] quote: [[PPO training analysis]], [[PPO-RNN training analysis]], [[PQN-RNN training analysis]], [[Count-bonus PPO-RNN training analysis]], [[Count-bonus PQN-RNN training analysis]], [[SIL training analysis]], [[SMDP skills training analysis]], [[Dyna-Q training analysis]], [[Combo training analysis]]. The count-bonus variants are two methods, so two notes; ablation units (R77) have their own section in the note of their method, never pooled into the tuned rows.
  - Video: `cases.csv` rows with `video = yes` are the cases for the scenes "Stuck, then solved", the deepest floor and deaths of [[2026-10-20-craftax-visualisation-production]]. The rule, per method and only the `tuned` unit: the 2 longest `stall` cases (latest checkpoint first, then length; the final checkpoint has 2 for every method but dyna-q, whose second is its checkpoint 148 case), the first `deep_floor` case (a floor 1 case where one exists, else the overworld episode with the most achievements) and the first `death` case (the most frequent cause). That gives 4 rows per method, 36 of 291 at 1M; every other row, ablation units included, reads `no`. The 36 ids are tracked in [[Video cases 1M]], the source to re-apply the flags from. Flagged rows have their rollout, master, GIF and, for stalls, overlay on disk.
  - Hugging Face release: `outputs/analysis/<budget>/<method>/` (`hard/`, `cases.csv`, `obstacles.csv`, `obstacles.md`, `plots/`, `gifs/`, `overlays/`, `cases/<id>.json`) is the per-method package of [[2026-10-20-craftax-huggingface-release]]; the budget-level `outputs/analysis/<budget>/cases.csv` and the per-method copies stay as written by `write_cases` (same columns, one row set per method) and differ from it only in `video`.

## Invariants

- Runs belong to a phase by their `phases` tag, never by experiment name; statistics are per (method, `config_ref`): `select` refuses to pool them unless told to.
- Loading checks the contract columns, a unique `run_id`, the phase tag, that curves and episodes belong to a run of `runs`, and that the episodes' `method`, `config_ref` and `budget` equal the run's.
- A phase that was not exported (`final-1b`, `combo-1b`) raises `MissingPhaseError` naming it; `skip_missing=True` loads only the phases that exist, and an incomplete export still raises.
- Parquet-only use imports neither JAX nor MLflow: `CONTROLS`, `BASE_CONTROL` (module attributes built on first access) and `pair_of` import the registry when used; `CONTROLS` never holds combo.
- Controls come from `select_pair.controls_of` and `SKILL_METHODS`, never copies; a combo run's base control is read from its own `config_json` pair (`combo_pair`), never from combo.yaml.
- Literature is compared like with like only: training-episode score at 1B with block A, at 1M with block D, stochastic evaluation at 1B with block A2; greedy evaluation and stochastic at 1M have no block and raise. Blocks A3, B, B2, C, C2, C3 and E to I are not in the CSV.
- The CSV copies the note's cells as written; `spread` is set only when the score cell states an sd or s.e. of the % score itself (a raw-return sd, a CI or an sd of another variant gives `spread_kind` `none`; `score_text` keeps the cell). Nothing is recomputed from figures. After a note edit the test against the note shows which rows drifted.
- `protocol` follows one rule: the block's protocol, except `n.r.` when the row's source note says it is unstated or undocumented; block D has no heading protocol, so it is read per row from the notes. T2 shows it, because block D's Simulus row is a test-episode score.
- Every `note` value is the stem of a file in `research/Existing Implementations/`.
- A detector whose series, base-control series or input frame is missing reports `not logged`, `needs replay (evaluation Task 6)` or `needs eval actions`, never `absent` (R78); `table_rows` counts runs as detected over judged (detected or absent) and lists the others.
- Thresholds are module constants. Plateau is relative to the run's best score except at `ABSOLUTE_BUDGETS` (1B: 1 point); bonus starvation is `uninformative at 1M` (`STARVATION_BUDGETS`) (R79).
- `detect_all` judges one (method, `config_ref`) unit per call (R77); combo runs keep the method detectors of their own pair. Base pools are per method, never mixed: a control's exploration failure needs fewer floors than every other control, each named in the evidence.
- A base run that never logged a series (`first_unlock/*` in the reused runs) is left out of the base median, never counted as never unlocked; the evidence gives the runs used and left out (R78).
- Per-skill stats are required one by one (`smdp/skill/*/<stat>`, each deep skill's `chosen_share`), so one missing stat reads `not logged`.
- The `hard` summaries group by (`method`, `config_ref`, `budget`) themselves, so tuned and ablation runs in one frame stay apart (R77); intervals are `stats.stratified_bootstrap_ci` over seeds (one run per seed, 10,000 resamples), skipped only when every seed has the same value.
- `hard` reads only the event stream (`max_floor`, `ach/*`, `unlock_step/*`, `cause_of_death`, stall frames); the replay-only fields (`gathered/*`, `used/*`, `coverage/*`, `survival/level/*`, a stall's `intrinsics` and `inventory`) are never read, so a missing replay never becomes 0. Undefined values are NaN or a status: a checkpoint without deaths has a NaN share, a unit without stalls NaN median length and escape rate, a missing training series `train_seeds` NaN and status `never in eval` (never asserted as `never`, R78).
- Final checkpoint and stochastic mode are the defaults of every `hard` summary (thresholds' basis); an achievement's `seeds_ever` counts both modes and every checkpoint. `ACHIEVEMENTS` floors are home floors checked against the game: mob floors from `FLOOR_MOB_MAPPING`, ore (sapphire, ruby on 2), chest loot on its first floor (bow, chest, potion 1; books, so spells and enchanting, 3), crafting on 0; `started_by` ties break by `.value`. Plots name mode and scope in their title and refuse a table that mixes them; `achievement_status.png` draws `never` (solid cross) and `never in eval` (hollow diamond) apart.
- Cases are found per (method, `config_ref`), tuned unless an ablation is named (R77), in stochastic episodes. Scope per kind: stalls at each run's final checkpoint plus the longest at 3 earlier checkpoints (spread evenly over those with an escaped stall); deep floors over every checkpoint; rare unlocks at any checkpoint, the final one preferred; deaths at each run's final checkpoint. Ties break by fixed columns, so a rerun gives the same table. A deep-floor case on floor 0 peaks at its last unlock (every episode starts on floor 0).
- Windows: a stall case runs from the stall start to 20 steps after the unlock at 8x; other kinds 150 steps before to 49 after the peak at 1x; a GIF keeps the last 20 s of its window, so it ends with the peak. An export whose master replay diverges from the stored episode raises.
- `export_case` renders the overlay into a temporary directory and moves the clip, so `render_overlay`'s work files never reach `out_dir`; it refuses an `out_dir` outside `root` before any work (file columns are relative to `outputs/`).
- `find_cases` and `write_cases` import neither JAX nor MLflow; the replay side imports JAX inside the functions. Exports write only under `out_dir` and `root`, never the store (R85).
- Instability and collapse pass `stability`'s drawdown floor: 1 point at `ABSOLUTE_BUDGETS`, else `max(0.1, 0.25 x` the run's best smoothed score), named in the evidence (R92).
- Flat score (bonus distraction, reward hacking, re-trying) is a documented choice: the method plan says "flat (drawdown definition of evaluation-and-metrics)" and evaluation defines only drawdowns, so flat is a gain over the trailing 10% of the budget below 5% of the run's best smoothed score (`FLAT_WINDOW`, `FLAT_GAIN`).
- Bonus-driven re-trying takes the pair count from the Dyna-Q model graph and the success rate from the eval ends of that pair at the checkpoint: the model stores no success flag.
- `DETECTORS` is built on first access (owners of the skill detectors are `select_pair.SKILL_METHODS`); importing `obstacles` imports neither JAX nor MLflow.

- Comparison: every table runs per benchmark and block; the three controls are the reference rows of both blocks and a method never meets one of the other block (PoI matrix, race). IQM, PoI and Mann-Whitney exist at 1M only, with one Holm family per block (T1: block methods x controls; ablations: the block's ablations); 1B rows give mean, median and CIs and are indicative.
- T1, T2, T3, T4, T6 and the PoI matrix use the tuned runs; ablations appear only in `ablation_table`, each against its own method's tuned runs (R77). T2 shows our training score beside block D (1M) or A (1B) and the stochastic eval beside A2 (1B); never two blocks in one group.
- The gate reads only the published config's runs, skips budgets without runs (R86) and reports instead of raising; T2 carries its status, gap and `h` on the control rows. T2 gives a CI verdict only against rows of our protocol.
- Race (T6): per method `n` = runs that logged `first_unlock/*` (R78), `k` = runs that unlocked; medians are lower medians over all n runs with +inf for a never-unlocked run (as the obstacles base medians); eligible at k >= n / 2; lowest median wins, wall-clock only within one profile; never-logged methods read NaN wins, not 0. Laptop wall-clock (race, T4) is context only and says so in `wall_note` or `note` (R97, two concurrent workers).
- T6 weights seeds equally, the top cause of death included (mean per-seed share of deaths).
- T3 uses `obstacles.drawdown_floor` (R92), the detectors' own rule.
- Tuning optimism (R101, R102) compares the tuning mean only with fresh final seeds: reused seeds are the very runs the selection saw, so including them would shrink the winner's curse.

- The training CLI keeps units apart (R77): tables and plots take all units of a method (one `config_ref` per line or panel), `detect_all` and `find_cases` run per unit, and `write_cases` gets all units of the method in one call (it merges by method only). `--out` must end in `analysis`: case files are relative to its parent (`outputs/`).
- Optional detector inputs never fail a run: a run without eval actions or replay files gets the detectors' "needs ..." status. `skill_ends` and `eval_inventory` rows of a run are used only when its final checkpoint has them (the detectors read the frame's last checkpoint), and only stochastic ones are read.
- A method folder is complete when `.complete` exists (written after every case replayed) and logged when `.logged` exists (the MLflow run id). A rerun skips complete methods, logs the unlogged ones and redoes the rest; `--force` empties the folder and the method's flat `case-<id>.npz` files first. A failed case leaves the other cases and methods done, is written to `failed.json` (its partial flat rollout is removed, also on the next reset), withholds `.complete` and exits 1; a method that exports no case loses its rows in the budget table. Any other error stops the command: rerun it. The CLI refuses a run whose estimated disk (0.25 GB per unit, plus the logged copy) exceeds the free space.
- Logging: experiment `analysis` (get-or-create), run `training-analysis-<budget>-<method>` reused by name with its artifacts replaced (through `orchestration.tracking.log_analysis_run`, shared with the export: new files are uploaded first and the old artifacts the upload lacks are deleted after, raising if a delete fails; `masters/` stays out unless `--log-masters`: a case is about 6 MB of master video, 9 MB of GIF, 1 MB of overlay; `--phases` loaded is the `analysis/phases` tag); tags `analysis/kind=training`, `analysis/phases`, `analysis/budget`, `analysis/method` only (loaders select training runs by `phases`, `method`, `budget`, `seed`, `config_hash`).
- Store (R85, R103): `run_dirs` is one short read-only query per method that closes at once; `?timeout=<s>` in the URI is the busy timeout (default 300 s), stripped for the file name and kept for MLflow's SQLAlchemy URI. The CLI writes the store only through MLflow logging.
- Importing `training` imports neither JAX nor MLflow (`_open_run` and the logging import them when used).
- Figures read their numbers from the tables of `compare` (T1 for F2, `poi_matrix` for F3, T2 for F4's published marks, `achievement_status` for F5, T7 and `stability.config_scores` for F18, `run_stability` and T3 for F19, T4 for F20) and from `evaluation.stats` (`curve_band`, `step_grid` for F1); a statistic is never recomputed in `figures`. Only Craftax-1M is drawn without a note: a budget without runs is left out and the figure's note says "Craftax-1B pending" (F3, a 1M figure by design, says only that 1M is needed); 1B panels that exist are marked indicative and show median and mean (t interval) in F2, never IQM. With no runs a figure is a placeholder reading "no data". A panel is never an empty unlabelled axis (an unmeasured hardware panel reads "n.m.").
- A method has one colour in every figure and theme; a method missing from `METHOD_COLORS` raises. Ablations (R77) are their own dotted rows or curves, never pooled into the tuned method. A block is never ranked against the other: F2, F3, F5 and F1 show the blocks apart, the controls repeated in each. F20's laptop wall-clock and SPS carry the R97 note ("two concurrent workers, context only") from T4's `note` column; profiles are never compared. Every drawn artist carries a `gid` (`<kind>/<budget or phase>/<block>/<method>/<config_ref>`).
- F21-F28 take their intervals from `evaluation.stats` (`curve_band`, `stratified_bootstrap_ci`) and their tables from `compare` (F24 `ablation_table`, F25 `tuning_optimism`, fresh seeds only, R102); F23 shows significance as the critical-rho band, not a bootstrap; each figure's note names its known confound (epsilon decay in F21, ties and the training-score target in F23, selected tuned seeds in F24, 3 tuning seeds in F25, reverse causation of length in F26, between-method pooling in F27, unequal input sets in F28); F27 and F28 never write into the interpretation folder and never read an unfinished policy. Their legends sit above the panels in up to 3 columns in the report column (fewer when too wide); a one-entry legend becomes a note, and F22 rows no method can fill are named in the note, not drawn.
- `video` is set from the id list of [[Video cases 1M]], not by code: `write_cases` rebuilds a method's rows with `video` = "" and `analysis.training --force` resets it, so the list is applied again after any rerun, to the budget table and to the per-method copies together. The `cases.csv` files logged in MLflow run `training-analysis-<budget>-<method>` predate the marks and keep `video` blank; the files on disk are the hand-off.
- A results note holds only numbers of the files of its method folder and of `outputs/metrics/<phase>/runs.parquet`; "not logged" (R78) and "uninformative at 1M" (R79) are copied from the detector statuses, never replaced by a number.
- [[Final results]] holds only numbers of `outputs/results/tables/*.csv` and `report/numbers.tex` of one comparison run, each table section names its file, the ablations (R77) and tuning optimism (R102) stay apart from T1, and hardware figures are marked context only (R97); a rerun of the comparison (or the 1B finals) means the note is regenerated by hand from the new files, never edited number by number.

## Known issues

- `export_case` replays a stall case's episode five times: `as_rollout`, the master render and `render_overlay` (its own `EvalRun`, which replays for the observations, the network outputs and the frames); sharing one replay needs an `EvalRun` or episode parameter on `as_rollout` and `render_overlay` ([[visualisation]]).
- Key aliasing, survival failure despite flags and bonus-driven re-trying need the `skill_ends` replay frame, and hoarding under log2 keys (the tuned count-bonus-pqn-rnn config) the `eval_inventory` frame; until evaluation Task 6 builds them they read `needs replay (evaluation Task 6)`. The 1M production run had both frames in the export, so none of its 2410 verdicts reads `needs replay` or `needs eval actions`.
